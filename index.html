Crop Disease Detector — Project Proposal

1. Problem Statement

Farmers, especially in developing regions, often lack access to agricultural experts who can quickly and accurately diagnose plant diseases. By the time a disease is identified through traditional means, it has frequently spread beyond the point of effective treatment, leading to significant crop loss and economic hardship. There is a clear need for an accessible, instant, and trustworthy diagnostic tool that not only identifies the disease but also tells the farmer what to do about it.

This project builds a Crop Disease Detector — an AI-powered web application that lets a farmer upload a photo of a diseased leaf and instantly receive:

  1. The predicted disease (with confidence score).
  2. A visual explanation (Grad-CAM heatmap) showing which parts of the leaf the model focused on to make its decision.
  3. Actionable treatment recommendations — specific fungicides, dosage, organic alternatives, and preventive measures tailored to the diagnosed disease.

2. Dataset

PlantVillage Dataset (Kaggle)

  • ~54,000 labeled leaf images
  • 38 disease classes across multiple crop species (tomato, potato, pepper, apple, grape, corn, etc.)
  • Pre-split into train/validation/test sets
  • Clean, well-documented, and widely used as a benchmark

Known limitation (which we address): The dataset contains mostly lab-condition images with uniform backgrounds. Models trained on it can appear highly accurate while failing on real-world field photos. Our robustness testing (see Section 5) explicitly investigates this gap.

3. Model & Architecture

Base model: Fine-tuned ResNet50 (or EfficientNet-B0) via transfer learning.

Why transfer learning:

  • Pretrained ImageNet weights provide strong low-level feature extractors (edges, textures, color gradients).
  • Fine-tuning only the later layers drastically reduces training time and data requirements.
  • Proven to achieve >95% accuracy on PlantVillage with modest compute.

Training pipeline:

  • Input: 224×224 RGB images
  • Augmentation: random flips, rotations, color jitter, RandAugment
  • Loss: Cross-entropy with class weights (to handle class imbalance)
  • Optimizer: AdamW with cosine annealing
  • Early stopping on validation F1

4. Core Differentiator: Explainability + Treatment Engine

Most student projects stop at "predicted class + confidence." Ours goes two steps further.

4.1 Grad-CAM Visual Explanations

What it does: Generates a heatmap overlaying the input image, highlighting the regions the model considered most important for its prediction.

Why it matters:

  • Builds trust: A farmer (or evaluator) can see the model is looking at the diseased spot, not the background.
  • Supports bias analysis: Reveals whether the model is "cheating" by learning dataset artifacts (e.g., uniform backgrounds) instead of actual disease patterns.
  • Debugging tool: If the heatmap highlights irrelevant areas, we know the model needs retraining or better augmentation.

Implementation: pytorch-grad-cam or captum library, integrated directly into the Streamlit UI.

4.2 Treatment Recommendation Engine

What it does: After diagnosis, the app displays a structured treatment plan specific to the detected disease.

Content per disease class (38 total):

Field Example (Early Blight – Tomato)

Field Example
Cause Fungus Alternaria solani
Chemical treatment Chlorothalonil or Mancozeb spray, every 7–10 days
Organic alternative Neem oil spray, copper-based fungicide
Immediate action Remove and destroy infected leaves; avoid overhead watering
Prevention Crop rotation, resistant varieties, proper spacing for airflow
Severity guidance If >30% leaf area affected, consider removing the plant

Implementation approach:

  • Phase 1 (MVP): Curated JSON/dictionary mapping each of the 38 classes to treatment info, sourced from agricultural extension documents (FAO, university guides).
  • Phase 2 (stretch): RAG pipeline over agricultural PDFs using LangChain + vector DB for more nuanced, context-aware advice.

5. Real-World Robustness Testing

The problem: PlantVillage's clean lab images don't represent real field conditions — soil, shadows, multiple leaves, blur, varying lighting.

What we'll do:

  1. Collect ~100 real-world field images (from PlantDoc dataset, Google Images, or iNaturalist).
  2. Run the model on them and record the accuracy drop (expected: ~98% → ~60%).
  3. Apply mitigations: test-time augmentation, background removal (rembg), or fine-tuning on a small field-image set.
  4. Report before/after results.

Why this matters: It transforms the project from "I trained a classifier" to "I built and rigorously evaluated a real-world diagnostic tool." This is the kind of finding that earns high marks for Technical Implementation and Experimental Rigor.

6. User Interface (Streamlit)

Flow:

  1. User opens the hosted web app.
  2. User uploads a leaf photo (drag-and-drop or camera capture on mobile).
  3. App displays:
    • Predicted disease name + confidence score
    • Grad-CAM heatmap (original image side-by-side with highlighted version)
    • Treatment plan (structured card with chemical, organic, immediate, and preventive advice)
    • Confidence warning if score < 70% ("Please upload a clearer image")
  4. Option to download the diagnosis as a PDF report.

Hosting: Streamlit Community Cloud (free) + model hosted on Hugging Face Hub or GitHub Releases.

7. Evaluation & Bias Check

Metrics:

  • Overall accuracy, macro F1, per-class precision/recall
  • Confusion matrix (38×38)
  • Top-3 accuracy

Bias check:

  • Per-class performance breakdown → identify which diseases the model struggles with
  • Class imbalance analysis → does the model favor majority classes?
  • Grad-CAM analysis → does the model focus on disease regions or background artifacts?
  • Robustness gap → lab vs. field image performance

Bottom line

This is a feasible, well-scoped project that hits every rubric line. The Grad-CAM + treatment engine combo transforms a common classifier into a genuine decision-support tool, and the robustness testing gives you a real finding to report. It's impressive, practical, and achievable in 2–3 weeks.
