\section{Data Cleaning \& Verification Implementation}
\label{sec:cleaning}

A data-centric engineering approach is mandatory for real-world computer vision reliability. Prior to partitioning and model training, raw image data undergoes an automated verification and deduplication pipeline implemented in \texttt{src/data/quality.py} and executed via \texttt{data\_scripts/check\_dataset.py}.

\subsection{Handling Missing and Corrupt Values}
In computer vision workflows, missing data corresponds to corrupted bitstreams, incomplete downloads, zero-byte file allocations, or broken headers that cause silent runtime training crashes:
\begin{itemize}
    \item \textbf{Binary Integrity Verification:} Every image file is parsed via Pillow (\texttt{PIL.Image.verify()}) to detect truncated JPEG bitstreams, malformed compression chunks, and unreadable headers.
    \item \textbf{Channel and Mode Verification:} Verified images are immediately reopened and decoded to ensure standard 3-channel RGB format consistency. Files exhibiting missing color channels (e.g., unintended single-channel grayscale or 4-channel RGBA buffers) are flagged and standardized or excluded.
    \item \textbf{Result:} Across the 54,688 raw candidate images scanned, all 54,688 files passed structural and RGB binary verification with zero unreadable or missing-byte files. The 150 PlantDoc field images similarly passed full binary integrity verification.
\end{itemize}

\subsection{Duplicate Removal and Near-Duplicate Quarantine}
PlantVillage contains repeated photographs of identical physical leaves captured under marginal lighting, scale, or orientation shifts. Unchecked random splitting of such duplicates causes severe data leakage between training and testing sets, artificially inflating benchmark accuracy:
\begin{itemize}
    \item \textbf{Exact Duplicate Elimination:} Cryptographic 128-bit MD5 hashes were computed over all raw file byte streams. Exactly 808 exact bit-for-bit duplicate copies were identified and purged.
    \item \textbf{Near-Duplicate Detection (Perceptual Hashing):} We computed 64-bit discrete cosine transform perceptual hashes (\texttt{imagehash.phash}) across all RGB images. Pairs within the same crop-disease class exhibiting a Hamming distance $\le 4$ were identified as near-duplicate observations of the same underlying physical specimen (1,376 near-duplicate copies identified and clustered).
    \item \textbf{Disjoint-Set (Union-Find) Quarantine:} A disjoint-set clustering algorithm aggregated linked duplicates into discrete group identifiers (\texttt{group\_id}). In the dataset partitioning phase (Section~\ref{sec:splits}), group-aware splitting guarantees that all exact and near-duplicate instances of a single leaf remain strictly confined to the same partition, preventing train-to-test leakage.
    \item \textbf{Clean Retention Summary:} To eliminate duplicate bias and enforce class balance, all duplicate copies and excess images beyond the 1,000-per-class threshold were pruned, yielding 31,694 verified clean unique leaf images.
\end{itemize}

\subsection{Outlier and Anomaly Management}
Input outliers in foliar diagnostic datasets manifest as dimensional anomalies and cross-class duplicate label noise:
\begin{itemize}
    \item \textbf{Dimensional and Aspect Ratio Outliers:} Images are scanned for dimensional anomalies deviating from expected square proportions. All raw samples were confirmed to adhere to canonical $256 \times 256$ pixels (1:1 aspect ratio), with zero dimensional outliers detected.
    \item \textbf{Cross-Class Label Noise Outliers:} The deduplication engine cross-references perceptual hash collisions across differing class labels. Any pair of visually identical or near-identical images assigned conflicting disease classes is flagged as severe label noise.
\end{itemize}

All audit results and cluster manifests are deterministically recorded into \texttt{splits/dedupe\_report.csv}.
