Do not add *.pdf or *.png to .gitignore — the compiled report/proposal and report figures must be in the repo. The data/* + !data/README.md pattern is deliberate: ignoring the folder itself (data/) would make the exceptions impossible.

Verify the ignore works (Leader runs this on Day 1, everyone re-runs before pushing):

git status --short                       # data/ and models/ must NOT appear
git check-ignore -v data/raw/x.jpg       # should print the matching rule
git ls-files | xargs -I{} du -k {} | sort -n | tail -5   # largest tracked files; none above ~5 MB
If a big file is ever committed by mistake, deleting it in a later commit does not remove it from history. Tell the Leader immediately, before pushing, and undo with git reset --soft HEAD~1.

12. Common pitfalls (read once)

  • Leakage: random splitting of PlantVillage puts near-identical photos of one leaf in train and test and inflates accuracy. That is why A1/A2 group near-duplicates.
  • Pre-augmented Kaggle copies look like “free extra data” but spread augmented copies of the same image across splits. Use the original images.
  • Normalising val/test with their own statistics is wrong — use the fixed ImageNet values for everything.
  • Class weights computed on all data leak test information. Train split only.
  • Absolute paths in CSVs break on teammates' laptops. Use relative paths and config.py.
  • Different label order per person breaks the model later. Everyone uses splits/class_names.json.
  • Field images with wrong labels or unclear licences hurt both the result and the report. Double-check and record.
  • Committing a big file — see the warning in section 4.
  • One person doing everything in one big commit — the commit analysis will show it.
